Projects

keep

Problem

When several AI agents work in one repository, each keeps its own to-do list. Two agents pick up the same task, or work starts on something blocked by another item.

What I built

A single Go binary that keeps one work queue in SQLite and serves it over MCP, so Claude Code and Codex read and claim from the same list. Items carry dependencies, so the ready list only shows work that can actually start. A local dashboard shows what is workable, what is blocked and which agent holds what.

  • Go
  • SQLite
  • MCP

interlock

Problem

Two coding agents editing the same checkout overwrite each other's changes, and neither one notices until the tests break.

What I built

Hooks that make each agent hold the files it is editing. When a second agent reaches for a held file, the edit is blocked before it lands and the agent is told who has it. A panel shows every hold, handoff and stopped collision as it happens.

  • Go
  • Claude Code hooks
  • Codex

The Tavern

Problem

An agent left to run on its own can push code nobody reviewed, or report work as done that it never checked.

What I built

Fifteen Claude Code plugins for writing specs, building in parallel and reviewing UX, each with guardrails. The git guard lets an unattended run commit locally but blocks every way of publishing, even when permissions are bypassed. A separate agent verifies the work instead of the one that wrote it.

sluice

Problem

Teams track DORA metrics by hand in spreadsheets, so the numbers are late and nobody trusts them.

What I built

A service that takes events from GitHub, GitLab and Slack, stores them in an append-only log in PostgreSQL, and works out deploy frequency, lead time, change failure rate and time to restore from that log. It ships as a distroless non-root image, scanned with gosec, govulncheck and gitleaks, with integration tests against a real database and its own Prometheus and Grafana dashboards.

  • Go
  • Connect-RPC
  • PostgreSQL
  • React
  • Prometheus

brik8s

Problem

Getting a hardened Kubernetes cluster onto small or disconnected hardware usually means a long checklist of manual steps.

What I built

A single-binary Kubernetes distribution with containerd and etcd built in. It starts CIS Level 1 hardened, with SELinux, FIPS mode and secrets encryption on by default, rotates its own certificates and mirrors images between nodes.
