keep

Why I built it

My team runs several AI coding agents in the same repositories, and each one kept its own to-do list. Two agents would pick up the same task, or start on something that was still blocked.

What it does

A single Go binary that keeps one work queue in SQLite and serves it over MCP, so Claude Code and Codex claim work from the same list. Dependencies keep blocked items out of the ready list, and a local dashboard shows what each agent holds.

  • Go
  • SQLite
  • MCP

github.com/gshepptech/keep

interlock

Why I built it

Running two agents in one checkout meant they overwrote each other's edits, and nobody found out until the tests broke. Nothing existing handled it across both Claude Code and Codex.

What it does

Hooks that make each agent hold the files it is editing. A second agent reaching for a held file is blocked before the edit lands and told who has it. A panel shows every hold, handoff and stopped collision.

  • Go
  • Claude Code hooks
  • Codex

github.com/gshepptech/interlock

recall

Why I built it

Every new agent session started knowing nothing about our codebase, and the same mistakes got made twice. I built a memory server so the whole team's agents share what they learn.

What it does

A self-hosted memory server that a team's coding agents read and write through MCP or plain HTTP: conventions, decisions, requirements and known errors, each scored for how fresh and trusted it is.

  • Python
  • PostgreSQL
  • MCP

github.com/gshepptech/recall

Quietword

Why I built it

People shipping apps built with AI coding tools rarely get anyone to look at them, and most security scanners produce reports they can't act on.

What it does

A free scan: paste a URL and get a plain-language report on five common holes, with what someone could do with each finding and what to fix first.

  • TypeScript
  • Next.js

github.com/gshepptech/quietword
